# Supabase workflow (v0.1)

## 1. Levantar entorno local

```bash
supabase start
```

Se usa al comienzo del día o antes de trabajar en issues que tocan base de datos.

## 2. Crear una migración

```bash
supabase migration new <nombre_descriptivo>
```

Ejemplo:

```bash
supabase migration new create_test_migration_log
```

Esto crea un archivo en `supabase/migrations/<timestamp>_create_test_migration_log.sql`.

## 3. Editar la migración

Editar el archivo generado y añadir el SQL necesario.
Ejemplo:

```sql
create table if not exists public.test_migration_log (
  id bigint generated by default as identity primary key,
  note text not null,
  created_at timestamptz not null default now()
);
```

## 4. Aplicar migraciones en local

```bash
supabase db push
```

Este comando aplica todas las migraciones pendientes a la base local.
Revisar que termine sin errores.

## 5. Verificar el esquema

- Comprobar que la tabla existe (Supabase Studio o cliente SQL).
- Actualizar `scripts/introspection/current-public-schema.sql`
  con el estado actual del esquema.

## 6. Reglas

- Nunca modificar el esquema directamente desde el dashboard de Supabase.
- Todo cambio de esquema pasa por una migración versionada.
- La introspección debe reflejar siempre el último estado aplicable de `dev`.
